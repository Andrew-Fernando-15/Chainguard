STAGE 2 – Case Management & Access Control
────────────────────────────────────────────────────────
• Create Case model (caseId, name, status, currentInCharge, history)
• APIs: list allotted cases, open case with permission checks
• Authorization middleware:
  - Is user allotted to this case?
  - Does user have permission for any evidence in this case?
• Frontend: show only allotted cases + proper denied messages

Goal: No one can see cases or evidence they are not allowed to see.

STAGE 3 – Real File Handling + Encryption
────────────────────────────────────────────────────────
• Accept actual file upload (multer)
• Encrypt file with AES-256-GCM before saving
• Store only encrypted file on disk
• Save file path + hash + category in MongoDB
• Implement evidence versioning

Goal: Real encrypted evidence files exist in the system.

────────────────────────────────────────────────────────
STAGE 4 – View / Download + Case Closed Logic
────────────────────────────────────────────────────────
• Separate View and Download permissions
• Forensic = View only
• Implement Case Status change (Pending → Active → Closed)
• On Closed: automatically revoke access for Investigating/Police/Forensic
• Judge & CBI keep access

Goal: Full permission matrix + case lifecycle working.
